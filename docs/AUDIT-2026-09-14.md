# Audit aplikasi Shaff Development — 14 September 2026

## Cakupan dan batas verifikasi

Audit ini meninjau alur board/detail task, kontrak respons API, endpoint mutasi, autentikasi, reset demo, scheduler task berulang, metrik dashboard, dan build production. Pemeriksaan endpoint live dilakukan tanpa login: `/api/health` mengembalikan `200` dengan database `ok`, `/dashboard/tasks` mengarahkan ke login, dan login yang sedang terpasang masih menampilkan kontrol reset demo. Mutasi live tidak dijalankan agar data pengguna tidak berubah.

## Temuan yang diperbaiki di repository

| Prioritas | Temuan | Dampak | Perbaikan |
| --- | --- | --- | --- |
| Kritis | `POST /api/demo/reset` tersedia tanpa login di production dan menjalankan penghapusan data transaksi, sesi, serta audit log, kemudian membuat ulang akun dengan password pilihan pemanggil. | Kehilangan data dan pengambilalihan akun. | Endpoint menolak request di production sebelum menyentuh database. Kontrol reset dan akun demo disembunyikan dari UI production. Pemeriksaan origin ditambahkan untuk development. **Perlu deploy segera; live belum berubah.** |
| Tinggi | Respons `PATCH /api/tasks/[id]` dan `POST /api/tasks` tidak memuat relasi `program` dan `assignee`, tetapi halaman board/detail mengganti state dengan respons itu dan langsung membaca relasinya. | Halaman crash setelah status dipindah atau task dibuat. | Query include bersama menyamakan bentuk data GET, POST, dan PATCH. Board juga menahan perubahan ganda pada task yang sama dan memulihkan hanya task yang gagal. |
| Sedang | Form tambah client, program, dan task memanggil `event.currentTarget.reset()` setelah `await`; referensi event tidak dijamin masih tersedia, padahal form sudah ditutup. | Penyimpanan berhasil di server bisa ditampilkan sebagai gagal di UI. | Pemanggilan reset yang tidak diperlukan dihapus. |
| Sedang | Proxy menolak scheduler tanpa cookie sebelum route dapat memeriksa `CRON_SECRET`; actor audit `system-cron` juga tidak memenuhi foreign key `User`. | Task berulang tidak dibuat oleh cron. | Route scheduler dapat mencapai autentikasi secret sendiri; audit sistem memakai actor `null`. Request tanpa secret atau sesi tetap ditolak. |
| Rendah | Endpoint migrasi rich text Admin tidak memeriksa origin request. | Kontrol CSRF tidak konsisten. | Pemeriksaan origin ditambahkan. |

## Temuan lanjutan

| Prioritas | Temuan | Tindak lanjut |
| --- | --- | --- |
| Sedang | `lib/data.ts` menghitung `activeClients` dari maksimal 100 client dan `overdueTasks` dari maksimal 20 task. `dueThisWeek` saat ini sama dengan jumlah task dalam sampel 20, bukan task yang jatuh tempo minggu ini. Angka dashboard bisa lebih rendah atau menyesatkan ketika data tumbuh. | Hitung metrik dengan query `count` terpisah sesuai scope dan rentang tanggal; biarkan batas sampel hanya untuk daftar ringkas. |
| Sedang | `GET /api/tasks` memuat seluruh task yang dapat diakses berikut checklist tanpa pagination. | Tambahkan pagination atau pemuatan bertahap sebelum volume task besar. |
| Rendah | Pencarian global membuka `/dashboard/tasks?q=...`, tetapi halaman tasks menginisialisasi query kosong dan tidak membaca parameter `q`. | Sinkronkan input pencarian board dengan URL. |

## Verifikasi

- `npm run typecheck`: lulus.
- `npm run lint`: lulus.
- `npm run build`: lulus pada hasil akhir.
- `npm audit --omit=dev --audit-level=moderate`: 0 vulnerability.
- Smoke test production lokal: login `200` tanpa kontrol reset demo, `POST /api/demo/reset` `403`, `POST /api/recurring-task-rules/run` tanpa secret/sesi `401`, dan `/dashboard/tasks` tanpa sesi `307` ke login.
- UAT perpindahan task dengan akun sebenarnya dan verifikasi data di database live memerlukan deployment serta sesi terautentikasi.

Konfigurasi backup/restore, volume privat, secret, jumlah replica, dan log EasyPanel tidak dapat disimpulkan dari repository atau endpoint publik; periksa langsung di lingkungan hosting sebelum menyatakan audit operasional selesai.
